# Functions & mechanics — mod-auto-loot

> Detailed function and mechanics reference. For pure content (what the module does, IDs, DB references), see `CLAUDE.md`.

## Module loader

### `AddSC_AutoLoot()`
- **File**: `src/mod_auto_loot_loader.cpp`
- **Caller**: `Addmod_auto_lootScripts()` (generated by the AzerothCore module system)
- **Effect**: creates a global `new AutoLoot_Player()` instance that registers itself with the `ScriptMgr`.

## Main class: `AutoLoot_Player : public PlayerScript`

The constructor registers exactly three hooks via constructor init list:
```cpp
PlayerScript("AutoLoot_Player",
  {PLAYERHOOK_ON_LOGIN,
   PLAYERHOOK_CAN_SEND_ERROR_ALREADY_LOOTED,
   PLAYERHOOK_ON_UPDATE})
```

### Hook 1 — `OnPlayerLogin(Player*)`
Sends a welcome message via `ChatHandler::PSendSysMessage(AOE_ACORE_STRING_MESSAGE)` (= acore_string `50000`) when `AOELoot.Enable=true`. Pure UX, no logic.

### Hook 2 — `OnPlayerCanSendErrorAlreadyLooted(Player*) → bool`
Always returns `true`. This suppresses the "Already looted" error that would otherwise appear when auto-loot touches an already-emptied corpse instance again.

### Hook 3 — `OnPlayerUpdate(Player*, uint32 p_time)` *(main logic)*

Frame tick. Bails out early when:
- the player is in a group (no auto-loot in groups, to avoid bypassing loot rolls),
- `AOELoot.Enable=false`,
- fewer than **4 free inventory slots**.

Otherwise:

#### a) Creature loot
1. `GetDeadCreatureListInGrid(creaturedie, range=10.0f)` — all dead creatures in a 10-yard radius.
2. For each creature:
   - `Loot* loot = &creature->loot;`
   - Accumulate gold into local `gold` (see step 3).
   - `loot->gold = 0;` so it isn't counted twice.
   - For each slot 0..maxSlot:
     - `LootItem* item = loot->LootItemInSlot(i, player)`
     - **Stackable items** (`itemTemplate->MaxCount != 1`):
       - Try `StoreLootAndNotify(player, item->itemid, item->count, creatureGuid)`.
       - On success: `SendNotifyLootItemRemoved(slot)` + `SendLootRelease(GetLootGUID())`.
       - On fail (full inventory) and `AOELoot.MailEnable=true`: `SendItemRetrievalMail(itemid, count)` + chat hint (acore_string `50001`).
     - **Unique items** (`MaxCount == 1`):
       - Only looted if `!HasItemCount(itemid, 1)` (player doesn't already own it).
       - In any case release the loot slot and send loot release.
   - After the iteration: if `loot` is non-empty (remaining items not looted due to limits) and the creature is dead:
     - `AllLootRemovedFromCorpse()`, `RemoveDynamicFlag(UNIT_DYNFLAG_LOOTABLE)`, `loot->clear()`, `RemoveUnitFlag(UNIT_FLAG_SKINNABLE)` if set.
   - If loot is empty: only remove flags.
3. Gold to the player:
   - `ModifyMoney(gold)`, `UpdateAchievementCriteria(LOOT_MONEY, gold)`.
   - Send `SMSG_LOOT_MONEY_NOTIFY` with `data << uint32(gold) << uint8(1)`.

#### b) Chest/GameObject loot
1. `FindNearestGameObjectOfType(GAMEOBJECT_TYPE_CHEST, 10.0f)`.
2. Only continue if the player has `HasSkill(186)` (= Lockpicking).
3. The chest must be `GO_READY` and not despawned.
4. `CastSpell(myObj, 2575, true)` — Spell 2575 = "Pick Lock", no cast time.
5. Iterate slots, each item via `StoreLootAndNotify`. On success: `myObj->DespawnOrUnsummon()`.

> Note: only chests, no mining/herbalism nodes — those used to run via `OnAfterGObjLoot`, which was removed (see `log.md`).

## Helper function: `StoreLootAndNotify`

```cpp
static Item* StoreLootAndNotify(Player*, uint32 itemId, uint32 count, ObjectGuid lootSource)
```
- Check `CanStoreNewItem` → on failure return `nullptr`.
- `StoreNewItem` → `SendNewItem` → **`sScriptMgr->OnPlayerLootItem(player, item, count, lootSource)`**.
- **Important**: the hook call is the entire purpose of this helper function. Earlier versions used `player->AddItem()` directly, which bypassed the hook and prevented mod-paragon-itemgen from stamping item stats.

## Configuration options (`mod_auto_loot.conf.dist`)

| Key | Default | Effect |
|-----------|---------|---------|
| `AOELoot.Enable` | `true` | enable module globally |
| `AOELoot.MailEnable` | `true` | send items by mail when the inventory is full |

## Performance notes

- `OnPlayerUpdate` runs **every frame**. The early bail-outs (group / disabled / inventory full) prevent logic for most players.
- `GetDeadCreatureListInGrid` is O(cells × creatures) — can become expensive on big AOE pulls (fortress wipes). Range fixed at 10.0f.
- There is **no cooldown/throttle mechanism** between auto-loot passes. If that ever becomes a problem, a per-player TimeOfLastRun check would be the obvious extension.

## Known limitations

- **No group support** — players in groups are skipped entirely because the module does not support loot rolls.
- **No mining/herbalism** anymore (see note above).
- **No skinning** integrated — the Skinnable flag is even removed when the corpse is empty.
- **No reagent routing into Endless Storage** — anyone using mod-endless-storage gets items into the inventory, not directly into storage. That would be a follow-up feature.
